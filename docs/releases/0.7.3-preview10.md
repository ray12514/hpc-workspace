# 0.7.3-preview10: packaged tool glibc isolation

On an older host, `bat` could start a Nix Bash wrapper and then a Nix executable while an inherited `LD_LIBRARY_PATH` selected the host's incompatible libc. The workspace now packages the underlying `bat` executable with a fixed Nix library path. The Fortran language server (`fortls`) similarly starts through the packaged Python interpreter instead of the Nix shell and Python wrapper chain. The workspace still preserves the host library path for native programs and site modules.

The focused [old-libc regression](../../scripts/test-glibc-toolkit) uses only public, disposable Docker images. It failed on preview9 with `GLIBC_2.38 not found`; the updated candidate passed for `bat` and `fortls`. The [diagnostic](../tool-library-diagnosis.md) collects command selection and safe library-path checks on an affected cluster pane. The separate native checksum `GLIBC_PRIVATE` report still needs those site results before its exact cause can be named.
