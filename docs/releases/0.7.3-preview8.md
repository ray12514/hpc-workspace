# 0.7.3-preview8: agent CA setup by gateway

The Codex and Pi gateway forms now ask for an optional local PEM CA path alongside the endpoint, model, and API key. Each named profile saves its own path. The selected agent receives it only for that launch: Codex through `CODEX_CA_CERTIFICATE`, Pi through `NODE_EXTRA_CA_CERTS`. A blank choice uses workspace defaults. Existing profiles retain their previous inherited CA behavior until edited, so review the CA choice when changing a vendor or endpoint.

For a native Codex configuration that needs a custom header, run `ws-codex-native-setup` once in a new workspace shell. It prompts invisibly for the gateway key and asks for a readable PEM CA path. Start Codex with `ws-codex-native`. The helper loads both values in a child shell, leaving the parent agents pane unchanged. Use `ws-codex-key-save` or `ws-codex-ca-save` to update just one setting. The native Codex TOML still owns the provider URL, model, and header name.

Keep `SSL_CERT_FILE`, `CURL_CA_BUNDLE`, and `REQUESTS_CA_BUNDLE` unset when the host's normal trust store already works for native downloads. The gateway forms and native Codex helper do not export these settings in the login shell. The CA file itself remains on the cluster and must be readable where the agent runs. No key or site certificate is included in the image.

The [Pulse assessment](../pulse-assessment.md#jaeger-check-before-the-next-image) found that Pulse currently emits Prometheus metrics, with no Jaeger trace source. Jaeger is therefore not part of this image. Continue to run Pulse's Prometheus and exporters as a separately managed deployment.

From a native login shell, run `git pull --ff-only && ./setup`, then start a **new** `ws enter` or managed session. Existing sessions keep their earlier image. The [gateway guide](../agent-profiles.md) and [native Codex guide](../restricted-codex.md#save-once-load-on-demand) have the setup steps.
