# 0.7.3-preview7: skills, key launch, and GPU monitor

The thin image already carried 26 skill folders, but entering the workspace did not place them where Codex discovers user skills. Entry now snapshots the bundled skills into a persistent, release-specific home directory and links them under `~/.agents/skills`. Existing personal skills and links to outside sources are preserved. Links previously managed by the workspace follow the selected release. The native Codex TOML remains the source of model and gateway settings; it is not used for skill discovery.

For a custom-header gateway, `ws-codex-native` loads the key saved by `ws-codex-key-save` in a child shell and starts the native Codex profile. The parent agents pane does not retain the key export. Keep `CODEX_CA_CERTIFICATE` in `~/.config/hpc-workspace/bashrc` if the gateway requires a site CA; new panes load that non-secret path automatically.

The image includes `nvtop` with AMD and NVIDIA monitoring support. AMD's open libdrm comes with the image; NVIDIA's NVML comes from the allocated node's installed driver through Apptainer's `--nv` integration. Use `ws enter --gpu cuda` or `ws enter --gpu rocm` inside a GPU allocation, then run `nvtop`. The image does not install a vendor driver or grant GPU access. GPU telemetry remains a site-local acceptance check.

After `git pull --ff-only && ./setup` from a native shell, start a **new** `ws enter` or managed session and then a new Codex process. Check `test -f ~/.agents/skills/codebase-design/SKILL.md && echo 'Workspace skills ready'`; use `/skills` inside Codex. Existing sessions keep their earlier image.
