# 0.7.3-preview6: site startup prompt correction

The affected RHEL system confirmed that the installed preview5 entry still lacks the `ws:` label. Its `/etc/bashrc` makes `PROMPT_COMMAND` read-only before Bash reaches the workspace configuration, so preview5's deferral begins too late.

This release starts the final interactive Bash without automatic rc files, then sources `/etc/bashrc` while the workspace's narrow prompt-readonly deferral is active. It retains the site's hook and read-only choice, places the workspace prompt and restore hooks around the site command, and keeps the current path visible after directory changes.

The managed editor window starts a fresh shell when Neovim exits. This release also prevents that second shell from treating the workspace's temporary bootstrap hook as a site hook. A packaged regression confirms the `ws:` label and a read-only site hook survive the restart, and the editor window remains usable as a shell.

The operator ran the repository-only candidate on the affected RHEL system before this image build. It reported `candidate_visible_label=yes`, `candidate_prompt_hook=present`, `candidate_prompt_template=workspace`, and a read-only four-element prompt array. The installed preview5 entry reported `actual_label=no`. After installing preview6, the operator confirmed that a fresh workspace entry showed the expected prompt. No site startup file, credentials, or full hook text was collected.

From a native shell in the updated checkout, run `git pull --ff-only && ./setup`, then start a new `ws enter`. Existing managed sessions retain their old image; stop and recreate a session to use this release there.
