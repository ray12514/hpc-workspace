# 0.7.3-preview5: compound read-only site prompt hooks

The affected RHEL system confirmed that `scp` works in preview4. Its prompt still lacks the `ws:` label. The sanitized fresh-entry check found one scalar, read-only `PROMPT_COMMAND` containing shell code, rather than the single function that preview4 could wrap. The workspace label value is set, but the site command changes `PS1` before Bash displays it.

This release defers a `readonly PROMPT_COMMAND` declaration while Bash startup runs. After all startup files load, it places the original site command between the workspace's prompt and restore hooks, then makes `PROMPT_COMMAND` read-only again. Other `readonly` declarations retain their normal behavior. The fallback for sites that lock the variable through another mechanism remains available.

A PTY regression uses a personal startup file with a compound, read-only command that resets `PS1`. It fails against preview4 and passes with this change, including the original site's output and the workspace path after `cd`. The packaged Linux Bash 5 prompt tests also pass. The affected RHEL site's exact startup files remain private; a fresh `ws enter` there is the acceptance check.

From a native shell in the checkout, update with `git pull --ff-only && ./setup`, then start a **new** `ws enter`. A running tmux server keeps its original image and shell until stopped and recreated.
