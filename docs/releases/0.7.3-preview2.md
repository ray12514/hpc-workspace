# 0.7.3-preview2: workspace prompt on sites with a read-only hook

**Follow-up:** The affected RHEL system still reported the read-only error and a missing workspace label with this release. Use [0.7.3-preview3](0.7.3-preview3.md) for the subsequent correction. The validation below describes the synthetic fixture used at this release, not a confirmed site fix.

This preview keeps the colored `ws:SITE CONTEXT@NODE` prompt when a site's Bash initialization makes `PROMPT_COMMAND` read-only. The prior image tried to add its prompt hook to that variable, printed `PROMPT_COMMAND: readonly variable`, and could show a blank workspace identity. The new shell checks the attribute before writing to it. If it is read-only, the shell preserves the site's hook and shows the workspace identity and current directory through its own prompt.

In that fallback, the workspace's Git branch and last-command status decorations are unavailable because they require the prompt hook. Normal writable-hook shells keep the full prompt. This change does not alter session state, native site commands, Codex, or Pi.

Update from a native shell with an existing checkout:

```bash
git pull --ff-only && ./setup
```

Start a new `ws enter` or `ws session` after installing. Existing tmux sessions retain their recorded image. For a manual transfer, use this release's four artifacts and four matching checksum files together; see the [transfer guide](../thin-start.md#manual-bundle-transfer-optional).

The regression reproduces the error with the packaged 0.7.3-preview1 Bash and a synthetic site module initializer that sets a read-only hook. The same packaged Bash with the corrected startup file keeps the site's hook, workspace label, color, and changing directory. A real site's Bash and module initialization still need a local check. See [troubleshooting](../troubleshooting-startup.md#prompt-command-is-read-only-or-the-workspace-label-is-missing) and [validation](../validation.md).
