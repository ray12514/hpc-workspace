# 0.7.3-preview9: named Codex team gateways

The Codex gateway form now offers `custom-header` authentication. Enter the exact HTTP header name supplied by the gateway, then choose a stored key or a gateway-specific environment variable. The form keeps the header name, endpoint, model, key source, and optional CA path with each named profile. `ws agent codex team-a` and `ws agent codex team-b` start separate child processes with only the selected key. Existing Bearer profiles continue to work. The key value is hidden in the form and stored only in the private credential file when stored-key mode is chosen.

`ws-codex-key-on/off` and `ws-codex-native` serve the separate native Codex configuration and do not select named profiles. Pi named profiles continue to support Bearer and `x-api-key` gateways; use Pi's native configuration for a different custom header. See [gateway setup](../agent-profiles.md) and [site-provided Codex settings](../restricted-codex.md).

The offline packaged-client fixture exercised the real Codex custom-header request against a local synthetic gateway and confirmed that it sent the selected key in that header without a Bearer header. It also exercised both terminal forms and the existing Codex/Pi routes. Cluster gateway acceptance, the exact site header name, and site policy settings require local confirmation.
