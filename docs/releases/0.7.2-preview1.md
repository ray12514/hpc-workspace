# 0.7.2-preview1: tmux session selection and location lookup

Commands and layout helpers running inside managed tmux now use that server's socket. Previously the workspace wrapper always added its release-default socket, even when the current pane belonged to a project-specific server. A bare `tmux` command could report no server or contact an unrelated concurrent session. This also affected layout helpers and their initialization. Explicit `-L` and `-S` selections remain supported.

This release also ships `ws sessions` and `ws sessions --json` in the host launcher, with private records of the node, project, image, release, and last record update. Existing 0.7.1 records can supply partial information. Only local keeper processes are checked; other nodes remain explicitly unverified. The lookup neither opens SSH connections nor kills or moves sessions.

Update from the repository checkout in your native Linux shell:

```bash
git pull --ff-only && ./setup
```

Start a **new** workspace session to use the corrected wrapper and initialize its layout helpers. Existing sessions retain their original image. Keep an old server alive if it holds an interactive job; save files and finish that work normally before retiring it. Kerberos delegation and credential renewal remain site responsibilities, described in the [reconnection guide](../session-locations.md).

If you need a tmux command to target an existing older session, use its **Ctrl-B :** command prompt. A shell-level alternative inside that session is `tmux -S "${TMUX%%,*}" COMMAND`, with the desired tmux command in place of `COMMAND`. This does not repair already-missing layout bindings or refresh credentials.

Tool versions and the Nix lock are unchanged. The custom-header Codex form and automatic thin-image skill activation remain outstanding; use the [native Codex configuration](../restricted-codex.md) for that gateway. The Windows guide uses only [built-in VS Code terminal features](../windows-vscode-hpc.md).

The new regression runs a managed server alongside a separate default server, executes a client and the actual layout-save helper inside a managed pane, and verifies the saved project's windows. It also checks an explicit socket override. See [validation](../validation.md) for the local image/runtime checks and their limits.
