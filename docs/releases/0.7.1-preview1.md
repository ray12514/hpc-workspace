# 0.7.1-preview1: readable configuration forms

`ws configure` uses the terminal's normal text and background colors for headings, input, choices, and help. Gum's fixed gray labels in 0.7.0 could be difficult to read on black backgrounds. The form keeps its interactive controls and cursor; API keys remain masked. This change is scoped to form processes, so shell/editor colors and standalone Gum preferences are unaffected.

Update from the repository checkout in your native Linux shell:

```bash
git pull --ff-only && ./setup
```

Start a fresh `ws enter` or `ws session`; an existing session keeps its original image. To check a connection that was entered through the old form, run `ws configure codex`, select the gateway, and choose **Edit connection**. Review the values before saving. Claude uses the same workflow through `ws configure claude`.

Basic prompts also work in 0.7.0: `ws configure codex --plain`. See the [profile guide](../agent-profiles.md) and [troubleshooting](../troubleshooting-startup.md#configuration-form-text-is-too-dark-to-read).

The package pins, tool versions, gateway configuration format, and installer behavior are unchanged from [0.7.0](0.7.0-preview1.md). The regression exercises the real packaged Gum in a terminal with xterm, xterm-256color, screen-256color, and tmux-256color settings, including conflicting inherited colors. It checks readable default-color rendering, existing and typed values, selection, hidden keys, cancellation, and basic prompts. See the [validation record](../validation.md) for artifact checks and their limits. No actual PuTTY client or cluster configuration was accessed.
