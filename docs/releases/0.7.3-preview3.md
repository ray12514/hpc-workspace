# 0.7.3-preview3: RHEL prompt startup correction

The affected RHEL system still printed `PROMPT_COMMAND: readonly variable` on 0.7.3-preview2. Its checks established that a clean workspace Bash started without error, loading the workspace Bash configuration produced the error, and an interactive workspace had the right release and label value but a replaced `PS1` template. A location-only trace pointed to generated code evaluated from the workspace Bash configuration. The packaged zoxide 0.10.0 [Bash initializer](https://github.com/ajeetdsouza/zoxide/blob/v0.10.0/templates/bash.txt) writes `PROMPT_COMMAND` too; a local reproduction with the published image produced the same trace location and error.

Normal `ws enter` and managed tmux windows now initialize site modules in a short-lived Bash, carry the module functions and existing site prompt hook into the final Bash, and compose the workspace prompt around that hook. Bash's read-only attribute does not carry across the process replacement, so the workspace can add its hook. Its prompt restoration runs after the site hook, retaining the colored `ws:SITE CONTEXT@NODE` label if that hook resets `PS1`. The site hook still executes. A direct Bash startup that bypasses `thin-shell` uses zoxide's `--hook none` mode when `PROMPT_COMMAND` is read-only, avoiding the error while retaining `z` and `zi` commands; automatic zoxide scoring is unavailable in that fallback.

Update from the native shell in the repo checkout:

```bash
git pull --ff-only && ./setup
ws enter
```

Start a new workspace or managed tmux server after installation. Existing sessions retain their original image. The local tests used a synthetic site initializer and the exported candidate SIF under Apptainer 1.5.3. They do not establish how the target RHEL site's exact startup files behave; report a remaining error with the [startup checks](../troubleshooting-startup.md#prompt_command-is-read-only-or-the-workspace-label-is-missing).
