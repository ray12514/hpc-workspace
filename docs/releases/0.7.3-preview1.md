# 0.7.3-preview1: Pi, managed-session controls, and editor shell

This preview brings the reconnect work into the installed launcher. From a native shell, `ws sessions` lists recorded projects and nodes, `ws attach --session NAME` reconnects to a selected running workspace using its recorded image, and `ws stop --session NAME` stops one selected local workspace and waits for its keeper to exit. Attach does not start a replacement session. A remote record identifies the original node; it cannot move live processes there or verify that node's current state. See [session locations](../session-locations.md).

The managed **editor** window now starts Neovim from a workspace Bash shell. `:wq` or `:q` returns to that window's prompt, where `nvim` reopens the editor. Other windows and the container keeper continue normally. Stopping the server still closes its panes and foreground work.

The image now packages **Pi 0.87.1 and Codex**. The workspace configuration menu offers named Pi gateway profiles with OpenAI Responses, OpenAI Chat Completions, or Anthropic Messages protocol selection. Pi can also use its own `/login` and `/model` for supported providers. Pi's credentials and sessions are independent of Codex. The packaged Pi binary is pinned to the upstream Linux release and checked by SHA-256. See [gateway profiles](../agent-profiles.md) and [agent setup](../editor-and-agents.md#ai-setup-and-local-checks).

The image also includes `ws-codex-key-save`, `ws-codex-key-on`, and `ws-codex-key-off` for a native Codex provider whose custom header reads `HPC_GATEWAY_KEY`. Saving uses hidden input and a private plaintext file; loading is deliberate in each shell. Put the non-secret `CODEX_CA_CERTIFICATE` path in [personal workspace Bash settings](../restricted-codex.md#save-once-load-on-demand) so new panes receive it. The key itself is never part of the image or source release.

This source release includes the [host-only session diagnostic](../../START-HERE-DIAGNOSTICS.md), [compute-agent test](../blueback-compute-agent-test.md), and [old-node cleanup handoff](../blueback-compute-handoff.md) from the former `codex/session-reconnect` branch. The broad old-node cleanup helper is separate from `ws stop`: use it only for the specific handoff procedure, after reviewing its target and impact.

Update from an already installed checkout on the target system:

```bash
git pull --ff-only && ./setup
```

Or download the four matching assets and checksums from the [0.7.3-preview1 release](https://github.com/ray12514/hpc-workspace/releases/tag/v0.7.3-preview1) and follow the [manual transfer guide](../thin-start.md#manual-bundle-transfer-optional). Start a **new** `ws enter` or `ws session` for the new image. An existing tmux server continues on its recorded old image until you finish or stop it; `ws attach` deliberately reconnects to that original image.

The Nixpkgs lock remains unchanged from 0.7.2; Pi replaces the previous second agent. Local fixtures validate the release bundle and Linux/Apptainer behavior; they do not prove login-node, scheduler, storage, certificate, or gateway behavior on a particular cluster. The nested Apptainer/Codex Bubblewrap observation and automatic activation of bundled agent skills remain separate work. Pi runs tools with the permissions of the account that launches it. See [validation](../validation.md), [Pi security](https://pi.dev/docs/latest/security), and [skills status](../skills.md).
