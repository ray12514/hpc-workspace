# HPC workspace 0.2.0-preview1

Daily appearance and native job submission for Ruth (PBS), Jean (Slurm), and Blueback (Slurm).

## Start here

Download the `.sif`, the explicitly named `hpc-workspace-source-0.2.0-preview1.tar.gz`, and both matching `.sha256` files. Transfer and verify them using the [startup guide](https://github.com/ray12514/hpc-workspace/blob/v0.2.0-preview1/docs/transfer.md). Use both the new image and matching launcher. Keep the previous release for rollback; existing shells and tmux sessions retain their original image and launch settings.

After selecting the new image, a login-host session can enable submission from its workspace shell:

```bash
ws session --site ruth --project "$HOME/my-project" --host-jobs
```

Inside that workspace, `ws submit --dry-run ./job.pbs` previews the request, `ws submit ./job.pbs` submits it, and `ws jobs` shows your queue. Use Slurm scripts on Jean/Blueback. The [daily workflow guide](https://github.com/ray12514/hpc-workspace/blob/v0.2.0-preview1/docs/daily-workflow.md) includes PuTTY setup, VS Code settings, native script examples, and environment details.

[See the Bash, tmux, and Neovim views](https://github.com/ray12514/hpc-workspace/blob/v0.2.0-preview1/docs/previews/README.md), captured from this image with local demo data.

## Changes

- Coordinated Bash, tmux, and Neovim appearance. The prompt shows site, node, project, Git branch, allocation ID when present, and the previous command's nonzero exit status. No icon font is required. Color controls support 256 colors, true color, and plain prompts.
- Host-side `ws submit` uses the installed PBS/Slurm client and returns native job IDs and errors. Scripts choose resources and job runtime; the development image is not automatically inserted into batch jobs.
- Optional `--host-jobs` provides the same submit/queue operations inside a login-host container through a private, same-UID Unix socket. No network listener or automatic retries. Paths are restricted to the session's project/work directories.
- Submissions use a selected host environment plus explicit `--env NAME` inputs. Container paths and AI keys are not automatically exported. Native job scripts still initialize their own site software environment.
- Core package and AI-client versions remain the same as the first preview. GPU software stacks, SquashFS payload activation, and MPI integration remain later phases.

## Validation and limits

See the [validation record](https://github.com/ray12514/hpc-workspace/blob/v0.2.0-preview1/docs/validation.md) for local test results. Automated scheduler tests use synthetic clients; no live scheduler or private cluster data is involved. The existing Docker Desktop limitation on direct nested SIF mounting remains documented, and local Apptainer fixtures use extraction (`--unsquash`). Normal mounting and scheduler integration must be checked locally on each target.

The release contains the SIF, source bundle, installed-package manifests, checksums, and a release record. No registry or Docker installation is required on the cluster. Host Python 3.6+, Apptainer, and native scheduler clients are required; persistent sessions also use host tmux. This is a personal development environment, not an official HPCMP release.
